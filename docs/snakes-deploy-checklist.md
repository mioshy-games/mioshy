# Snakes & Ladders - Deploy & Test Checklist

**Last update:** 2026-04-17

רצף הפעולות שצריך לעבור לפני ואחרי דיפלוי כדי להיות בטוחים שהמשחק עובד טוב במובייל ובדסקטופ, גם במצב מקומי וגם במצב מרחוק.

## 1. Supabase (חד-פעמי, לפני הדיפלוי)

הריצו את הקובץ הבא ב-Supabase SQL Editor (Project → SQL → New Query → הדביקו → Run):

```
supabase/migrations/023_snakes_default_config_and_dice.sql
```

מה הוא עושה: יוצר שורת קונפיג ברירת-מחדל פעילה בטבלת `snakes_ladders_config` (אם אין כזו), כדי שמשחקי remote יעבדו מהרגע הראשון. אידמפוטנטי - אפשר להריץ שוב בלי נזק.

אין צורך בשינויי סכימה נוספים. המעבר מ-coin ל-dice נעשה בתוך ה-JSONB של `game_rooms.game_state` ולכן לא דורש ALTER TABLE.


## 3. QA - מצב מקומי (Pass-the-phone)

1. כנסו ל-`/he/game` במובייל.
2. לחצו על הכפתור הגדול **🎲 לשחק עכשיו על מכשיר אחד**.
3. הוסיפו שני שחקנים לפחות, לכל אחד שם + אוואטר + צבע (האוואטרים והצבעים צריכים להיות ייחודיים - הבחירות שכבר נבחרו נעלמות לשחקן הבא).
4. לחצו **להתחיל משחק 🎲**.
5. לוודא:
   - הלוח תופס לפחות 70% מרוחב המסך במובייל ובדסקטופ.
   - הטוסט למטה מציג "מעבירים את המכשיר ל-<שם>" בתחילת כל תור.
   - הקובייה מסתובבת בעת לחיצה ומציגה ערך 1-6.
   - נפילה על סולם מעלה את השחקן + מושמע צליל עולה.
   - נפילה על נחש מורידה את השחקן + מושמע צליל יורד.
   - מודל שאלה/אתגר נפתח אחרי כל זריקה; כפתור "עניתי" ממשיך לתור הבא, "דילוג" חוזר X צעדים לפי ההגדרה.
   - כשמישהו מגיע ל-100 - מוצג מסך ניצחון, קונפטי בשלושה גלים, וצליל ניצחון.
   - כפתור "משחק חדש" מאפס את המשחק עם אותם שחקנים.
   - כפתור "חזרה ללובי" חוזר ל-`/he/game`.

## 4. QA - מצב Remote (שני מכשירים)

1. מכשיר A: `/he/game` → "צור חדר חדש" → שם → קבלתי קוד חדר 4 תווים.
2. מכשיר B: `/he/game` → "הצטרף לחדר קיים" → מקלידים את הקוד → שם.
3. שני המכשירים עוברים ללובי; כל שחקן בוחר אוואטר+צבע (locking).
4. Host לוחץ "התחלת משחק".
5. לוודא:
   - שני המכשירים עוברים אוטומטית למסך הלוח.
   - תורות מתחלפים נכון - רק השחקן הנוכחי רואה קובייה פעילה.
   - מצב המשחק (positions, phase, question) מסונכרן בין המכשירים בכ-1 שנייה (Realtime).
   - אם שני משתמשים לוחצים על הקובייה במקביל, רק אחד מצליח (RPC מונע כפילות).
   - מנוי בלתי-פעיל: אחרי 3 זריקות חינם בחדר אחד, מוצג SubscriptionModal.
   - בסוף המשחק, שני המכשירים רואים את מסך הניצחון; host יכול ללחוץ "משחק חדש".

---

## 5. QA - מובייל ספציפי (iOS Safari)

- הלחיצה הראשונה על הקובייה צריכה לשחרר את ה-AudioContext (iOS דורש user gesture). הצלילים אמורים להישמע מהזריקה הראשונה.
- ה-viewport לא צריך לגלוש אופקית; כפתורים גובה מינימום 48px.
- כיוון RTL: הטקסטים וסדר האלמנטים בצד ימין.

---

## 6. Rollback

אם משהו לא עובד בפרודקשן:

- **UI regression:** Revert של הקומיט באפליקציה.
- **DB:** אין Schema change, אז אין צורך ב-DOWN migration. אפשר לבטל את שורת הקונפיג הפעילה:
  ```sql
  UPDATE public.snakes_ladders_config SET is_active = false WHERE name = 'Mioshy Classic';
  ```
