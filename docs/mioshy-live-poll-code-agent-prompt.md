# פרומפט לסוכן קוד — הטמעת "סקר הזוגיות של ישראל" (מיאושי)

גרסה 2, 13.7.2026. הבריף המלא לסוכן הקוד. מרכז את האפיון שנצבר בשיחת העיצוב עם איציק. סמן כל הנחה, אל תמציא נתונים, ואל תעלה לפרודקשן לפני אישור.

## 0. תהליך העבודה ובטיחות (חובה, קריטי)
זהו ריפו **פרודקשן חי** (תשלומים, אבחון, משחקים). לעבוד מסודר ולא לשבור כלום.
- **branch נפרד בלבד** (`feature/relationship-survey`). אין נגיעה ב-`main`/פרודקשן.
- **פיצ'ר מבודד:** מוסיפים קבצים/ראוטים חדשים בלבד. **לא משנים ולא מוחקים קוד או פיצ'רים קיימים.** אם שינוי בקובץ קיים הכרחי — **עצור, הסבר למה, ובקש אישור לפני שאתה נוגע.**
- **להשתמש בקיים, לא להקים מחדש:** Supabase (DB+auth), Vercel (preview/deploy), ותשתית ה-Meta Pixel הקיימת (`docs/facebook-pixel-*`). התקנה/תשתית חדשה — רק באישור.
- כל שלב מסתיים ב-**preview URL נפרד** (לא הפרודקשן). **אין העלאה לפרודקשן לפני שאיציק ממזג ומאשר במפורש.**
- **רק אתה (סוכן הקוד) נוגע בקוד.** הסוכן המנהל חוקר, קורא, בודק, ומעביר דרישות/תיקונים.
- עבודה מול צ'ק-ליסט. בסוף כל שלב דווח: מה בוצע, קישור preview, מה נותר, ומה אתה צריך כדי להמשיך. חכה לאישור לפני השלב הבא.

## 1. מה בונים
ערוץ סקר יומי לזוגות, "סקר הזוגיות של ישראל". כל יום שאלה אחת עם שתי אפשרויות. אחרי בחירה רואים מיד באחוזים חיים כמה זוגות ענו כמוך וכמה הפוך. עברית, RTL, חינמי, ומזין לדשבורד ולשירותי מיאושי. גרסה ראשונה web, בהמשך אפליקציה עם פוש. **הסקופ כולל גם את העמוד השיווקי הראשי (עמוד הבית).**

## 2. מקורות אמת (לקרוא לפני שכותבים)
- **עיצוב הפלואו:** `mioshy-poll-flow.html` — ה-source of truth הוויזואלי. חמישה מסכים: שאלה, חשיפה חיה, הרשמה, שיתוף, ונחיתה בדשבורד.
- **לוגיקת האחוזים בהתחלה:** נספח הנוסחה ב-`mioshy-live-poll.docx` (ממוצע בייזיאני + Wilson).
- **הקשר מוצרי + מודל סמוך:** אפיון `Mioshy Daily`.
- **בנק שאלות:** פורמט 365 השאלות, רב-ברירה מצומצם לשתי אפשרויות.
- **דגשים גולמיים:** `mioshy-live-poll-code-notes`.

## 3. סטאק (הנחות לאישור לפני התחלה)
Next.js, שימוש חוזר ברכיבי השאלות של האבחון, פאנל אדמין, מיילים דרך ברבו. **לאישור:** בסיס נתונים (מוצע PostgreSQL), אירוח, ספריית auth. כל ה-UI עברית RTL, בשפת העיצוב של mioshy.com.

## 4. ישויות דאטה (סכימה מוצעת)
- **questions**: id, text, option_a, option_b, order_index, domain, is_active, prior_a, prior_b, prior_weight, insight_line (nullable), created_at.
- **votes**: id, question_id, option (a/b), user_id (nullable), anon_id, created_at. נשמר תמיד, גם אנונימי.
- **vote_aggregates**: question_id, count_a, count_b (מונים שמתעדכנים בכתיבה).
- **users**: id, name, email, phone, password_hash, subscribed (bool), terms_accepted_at, package_active (bool), created_at, couple_id (nullable), current_question_index.
- **couples**: id, link_code, user_a_id, user_b_id (שלב מאוחר).
- **user_question_history**: user_id, question_id, option, answered_at (ל"בלי חזרה" ולהיסטוריה).
- **push_tokens** (עתידי): user_id, token, platform.

## 5. הפלואו (חמישה מסכים, מהמוקאפ)
1. **שאלה**: לוגו + "סקר הזוגיות של ישראל" + שאלה במרכז + שתי תשובות כמרובעים עם טבעת גרדיאנט עדינה. הובר/בחירה = מילוי גרדיאנט + טקסט לבן. בלי פס התקדמות.
2. **חשיפה חיה**: השאלה + "בחרת: [תשובה]" + מונה חי (20px) + האחוזים כמספרים (בלי גרף/פס), התשובה שנבחרה מסומנת "כמוך" + CTA כתום (טקסט לבן) + לינק שיתוף (שחור, 18px). **חשיפה מיידית בלי חומת הרשמה.**
3. **הרשמה**: טופס מלא — שם, מייל, **נייד**, **סיסמה**, צ'קבוקס דיוור, צ'קבוקס תנאי שימוש, כפתור **"הצטרפות חינם"**.
4. **שיתוף**: כרטיס לוואטסאפ. **נגיש בלי הרשמה.**
5. **נחיתה בדשבורד** (אחרי התחברות): רואים שנחתנו על "סקר הזוגיות של ישראל". בסיידבר הימני, מתחת ל"השירותים שלנו", השירות מתווסף **כחמישי אחרי האבחון (הרביעי)**, ומסומן פעיל. **בהאדר: כפתור "דשבורד". בהמבורגר: "התנתקות".** כפתור ראשי: **"מעבר לעמוד הבית של מיאושי"** → העמוד השיווקי. טקסטים לא פחות מ-20px בדסקטופ ובמובייל.

## 6. הרשמה חובה + גישה לדשבורד (שינוי מהותי)
- הצטרפות לסקר היומי **דורשת הרשמה** (איציק שינה מהכיוון הראשוני). המטרה: שיירשמו לדשבורד ויגלו את שאר השירותים.
- קיים חשבון → **התחברות**. חדש → **הרשמה** (שם, מייל, נייד, סיסמה) + דיוור + תנאי שימוש.
- הצטרפות = **גישה לדשבורד**. המשתמש **נחשף לכל התכנים, אבל שום דבר לא פעיל עד רכישת החבילה המתאימה**.
- **תפריט ימני אחרי התחברות:** פריט חדש **"סקר הזוגיות של ישראל" / "שאלה יומית"**, עם אפשרות **הרשמה וביטול** קבלת שאלות (subscribe/unsubscribe).
- הערה: השאלה הבודדת, החשיפה והשיתוף נשארים **בלי הרשמה**; ההרשמה נדרשת רק כדי להצטרף לסקר היומי.

## 7. לוגיקת הצגה סדרתית (קריטי)
- מצביע `current_question_index` לשאלה הבאה לפי `order_index`.
- **בלי דילוג:** היעדרות לא מקדמת. בכניסה הבאה מקבל את הבאה בתור. בסוף עונה על כולן.
- **חייב לענות כדי להתקדם.** מי שלא ענה לא מקבל חדשה.
- **בלי חזרה:** שאלה שנענתה לא מוצגת שוב; רק ב**היסטוריה** רואים את כל התשובות.
- **אנונימי:** נעקב לפי anon_id (קוקי), כל ההצבעות נשמרות; בהרשמה מקשרים למשתמש.

## 8. אחוזים חיים + קולד-סטארט
- אחוז לאפשרות א = (prior_a + count_a) / (prior_a + prior_b + count_a + count_b) × 100. prior מהאדמין.
- **בלי גרף/פס בחשיפה** — רק מספרים. (הטווח המצטמצם/Wilson הוא לוגיקת הצגת המספר, לא ויזואליזציית פס.)
- האחוזים **תמיד מתעדכנים**: חישוב מחדש בכל קריאה; בנפח גבוה polling/push + מונים מצטברים.
- **אין מספרי הצבעה מומצאים.** הבסיס הוא הערכה אמיתית. פירוט ב-`mioshy-live-poll.docx`.

## 9. אדמין
- **העלאת CSV** של כל השאלות כולל הסדר (ראשונה, שנייה...). לפי סדר הקובץ, וניתן לשינוי באדמין (reorder).
- עריכת שאלה: טקסט, שתי אפשרויות, תחום, prior_a/prior_b/prior_weight, insight_line, is_active.
- **דשבורד התפלגויות** לכל שאלה (בסיס למדד הזוגיות).
- ניהול משתמשים ומנויים.

## 9א. מדידה ואירועי המרה בפייסבוק (Meta) — חשוב
- להטמיע **Meta Pixel + Conversions API (server-side)** בעמודי הסקר ובעמוד השיווקי.
- לירות אירועים לאורך המשפך: PageView, ViewContent (הצגת שאלה), ואופציונלי Lead (הצבעה/חשיפה).
- **אירוע ההמרה המרכזי = יצירת חשבון: `CompleteRegistration`** בהרשמה מוצלחת. זהו יעד האופטימיזציה של הקמפיינים בפייסבוק — המטרה הסופית היא יצירת חשבונות/הרשמות דרך עמוד הסקר.
- דה-דופ בין ה-Pixel (דפדפן) ל-CAPI (שרת) לפי `event_id`. לכבד הסכמת cookies/דיוור. לשמור Pixel ID ו-Access Token כ-env, לא בקוד.

## 10. עמוד שיווקי ראשי (בסקופ)
- העמוד השיווקי / עמוד הבית הראשי הוא חלק מהעבודה.
- **האדר** + **סטיקי במובייל**. לאשר ב-**preview לפני פרודקשן**.

## 11. זיווג בני זוג (שלב מאוחר)
- קוד שיוך כמו הקיים, רק אחרי התחברות. חשיפת תשובת בן/בת הזוג = פיצ'ר תשלום עתידי; לשמור דאטה מסודרת מעכשיו.

## 12. עתיד: אפליקציה + פוש
- לתכנן שיהיה קל להפוך לאפליקציה. יעד: ברגע שנרשמים → **נוטיפיקציית פוש** כשנשלח סקר/שאלה חדשים. לשמור push_tokens.

## 13. מה אסור
- מספרי הצבעה מומצאים; דילוג על שאלות; הצגה חוזרת של שאלה שנענתה; חומת הרשמה לפני החשיפה; העלאה לפרודקשן בלי אישור.

## 14. סדר עבודה מוצע
1. סכימת דאטה + מיגרציות. 2. ייבוא CSV + ניהול סדר באדמין. 3. מסך שאלה + הצבעה אנונימית + שמירה. 4. אחוזים בייזיאני + חשיפה חיה (בלי גרף). 5. לוגיקה סדרתית (מצביע, בלי דילוג/חזרה, היסטוריה). 6. הרשמה/התחברות + גישת דשבורד + פריט תפריט + subscribe/unsubscribe + **אירוע CompleteRegistration בפייסבוק**. 7. שיתוף בלי הרשמה. 8. עמוד שיווקי (האדר + סטיקי מובייל) + **Meta Pixel/CAPI**. 9. דשבורד התפלגויות באדמין. 10. שלד לפוש ולזיווג זוגות. כל שלב → preview → אישור.
