# 7 ימי ניסיון חינם (A3) - Spec

מצב: טיוטה לאישור Itzik. **money/Cardcom כבד → spec מלא → הסוכן מאשר פרמטר Cardcom → build → QA + preview (בלי חיוב אמיתי).**
מבוסס על 6 ההחלטות של Itzik (2026-07).

## עיקרון
המשתמש עובר את כל התהליך כולל **הזנת כרטיס אשראי, אבל לא מחויב** בהרשמה. הכרטיס **מאומת מול חברת האשראי + נשמר כטוקן (בלי חיוב)**. גישה מלאה ל-7 ימים. **ביום ה-7 מחויב** דרך הטוקן + ה-cron הקיים, לפי חוקיות המחיר/מבצע שהיו בעת ההרשמה. = דחיית החיוב הראשון ב-7 ימים.

## החלטות (נעולות)
1. **Toggle באדמין per-package** - בחירה אילו **מנויים** מציעים טריאל: games / journey-בלי-ליווי / journey-עם-ליווי (אחד, כמה, או שלושתם).
2. **חבילות זכאיות** - **מנויים בלבד**: games + journey (עם/בלי ליווי). **adults מחוץ** (one-time, לא מנוי).
3. **חיוב ביום 7** - **snapshot בעת ההרשמה**: שומרים plan_amount + promo_id + הבחירה (coaching) בעת ההרשמה, ומחייבים ביום 7 לפי מה שהיה אז (אם היה מבצע - לפי הגדרות המבצע ההוא).
4. **טריאל אחד** - לפי **טביעת-אצבע של הכרטיס (card fingerprint/token)** + חשבון. (fingerprint חזק יותר נגד ריבוי-חשבונות; החשבון תופס re-trial מאותו חשבון.)
5. **אימות בהרשמה** - חובה לוודא מול חברת האשראי שהכרטיס תקין **בלי לחייב**. ⚠️ **והמשתמש לא יראה שום חיוב - גם לא hold/pending זמני.** **כרטיס נכשל ביום 7 → התראה באדמין** (+ grace/retry קיים).
6. **Cardcom (נעול - אופציה A):** `CreateTokenOnly + IsCardApproval=true` → מריץ **J2** (בדיקת תקינות הכרטיס מול שב"א, **בלי חיוב ובלי hold** - הלקוח לא רואה כלום; חוזר flag `IsJ2ChackIsValid`). ❌ J5 (hold נראה) **פסול**. ⚠️ J2 מוודא שהכרטיס תקין אבל **לא בודק יתרה** - ייתכן כישלון חיוב ביום 7 (ההתראה באדמין מטפלת).
   - ⚠️ **בידוד סיכון:** J2/IsCardApproval דורש את **Cardcom v11** (`/api/v11/LowProfile/Create`), בעוד ש-openLowProfile הקיים על הממשק הישן ומשמש את **כל** הרכישות. **אסור לגעת ב-openLowProfile הקיים.** להוסיף **קריאת v11 חדשה ונפרדת רק לטריאל** (token+J2). הרכישות הרגילות (games/journey/adults) נשארות על הישן, ללא שינוי.

## מודל נתונים
- **subscriptions**: `status='trialing'`, `trial_ends_at timestamptz`, ו-snapshot: `trial_plan_amount`, `trial_promo_id`, `coaching` (כבר קיים). (או שדות trial_* ייעודיים.)
- **הגדרת זכאות באדמין**: per (product, coaching) - `trial_enabled boolean`. מקום: subscription_prices (עמודה) או site_settings. הסוכן יבחר הנקי.
- **מניעת ניצול**: טבלה/רשומה שמתעדת card fingerprint + user_id ל-trials שנוצלו; חסימת טריאל שני מאותו כרטיס/חשבון.

## זרימת הרשמה
1. המשתמש משלים את הזרימה → מזין כרטיס.
2. **Cardcom: tokenize + אימות בלתי-נראה** ($0/token-only, בלי חיוב וללא hold נראה). אם הכרטיס לא תקין → חסום, אל תתחיל טריאל, הצג שגיאה. (אם Cardcom לא תומך ב-$0 - ראה tradeoff.)
3. צור subscription `status='trialing'`, `trial_ends_at=now+7d`, snapshot של {plan_amount, promo_id, coaching}.
4. גישה מלאה מיידית ל-7 ימים.

## חיוב ביום 7
- ה-cron: כש-`trial_ends_at` הגיע → מחייב את הטוקן ב-snapshot amount (לפי המבצע מההרשמה). הסטטוס → active, ומתחדש רגיל.
- **כישלון חיוב → התראה באדמין** + grace/retry הקיים.

## ביטול תוך 7 ימים
- סימון canceled, **בלי חיוב**, שלילת גישה בתום הטריאל.
