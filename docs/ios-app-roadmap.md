# מיאושי — Roadmap לאפליקציית iOS

**מטרה:** אפליקציה להורדה ב-App Store, שנותנת למנויים גישה מהירה לתכנים ולצ'אט עם המומחה, עם נוטיפיקציות פוש. התשלום נשאר בדפדפן (מודל reader-app) — האפליקציה רק מאמתת מנוי קיים.

**עודכן:** 2026-06-23

---

## 1. נקודת הפתיחה — מה כבר קיים

הסריקה מצאה שכמעט כל המוצר כבר בנוי כ-web, mobile-first:

- **כל החוויה שאחרי ההתחברות** קיימת בקבוצת הראוטים `(shell)` — טאבים תחתונים למובייל, מסך בית (`/my/today`), שיעורים (`/my/lessons`), ציר המסע (`journey/timeline`), הגדרות.
- **צ'אט עם המומחה** — קיים ועובד (`/my/expert`, `app/actions/journey-messages.ts`).
- **תיבת התראות בתוך האפליקציה** — קיימת (`/my/notifications`).
- **התחברות** — קיימת (`/auth`, Supabase).
- **גישת מנוי (entitlements)** — קיימת (`lib/entitlements/getUserEntitlements.ts`), ה-shell כבר נועל תוכן ללא-מנויים.

**המשמעות:** לא בונים מוצר מחדש. עוטפים מוצר קיים במעטפת נייטיב.

### מה חסר (וזו כל העבודה החדשה)
1. מעטפת נייטיב (Capacitor) שעוטפת את האתר → נכנסת ל-App Store.
2. פוש נוטיפיקציות — **אין כיום שום תשתית פוש** (אין service worker, אין APNs). זה החלק האמיתי החדש.
3. התאמות reader-app: כפתור "להצטרף" פותח דפדפן; אפס מחירים/קנייה בתוך האפליקציה.

> **החלטה (2026-06-23): onboarding של 3 מסכים** בהפעלה ראשונה (מחזק את אישור אפל ב-4.2), ואז התחברות. אפשר לקצר ל-1 — מסך 1 עומד בפני עצמו. קופי + פרומפט תמונות בנספח א'.

**הערכת מורכבות כוללת: נמוכה-בינונית.** סדר גודל של ~2–3 שבועות עבודה ממוקדת של סוכן הקוד + זמן בדיקה של אפל. לא חודשים.

## 3. התוכנית — שלב אחר שלב

### שלב 0 — הקמת המעטפת
**סוכן הקוד:** מוסיף Capacitor לפרויקט, מגדיר את האפליקציה לטעון את אתר הפרודקשן (`server.url`), בונה פרויקט iOS שנפתח ב-Xcode.
**אתה:** מאשר התקנה על המכשיר שלך לבדיקה.
**תוצאה:** אפליקציה רצה על אייפון ומציגה את האתר הקיים. אבן דרך ראשונה.

### שלב 1 — Onboarding (3 מסכים) + כניסה
**סוכן הקוד:** 3 מסכי onboarding נייטיב בהפעלה ראשונה בלבד (נשמר ב-storage מקומי), ואז מסך התחברות הקיים (`/auth`). אם מחובר כבר — דילוג ישר ל-shell. קופי ותמונות: נספח א'.
**תוצאה:** הסבר קצר על השירות בכניסה ראשונה, ואז גישה מהירה.

### שלב 2 — פוש נוטיפיקציות
**סוכן הקוד:** משלב את OneSignal SDK, מבקש רשות פוש אחרי התחברות, מקשר את ה-token למזהה המשתמש ב-Supabase (OneSignal external ID), ומוסיף שליחת פוש מהשרת כשיש **תוכן חדש** או **הודעת מומחה חדשה** (התוספת נכנסת ל-actions הקיימים של ההודעות).
**אתה:** מעלה את ה-APNs Key ל-OneSignal; יכול לשלוח התראות ידניות מהדשבורד של OneSignal.
**תוצאה:** מנוי מקבל פוש → הקשה פותחת ישר את הצ'אט / התוכן הרלוונטי.

### שלב 3 — מודל reader-app
**סוכן הקוד:** כפתור "להצטרף" פותח דפדפן חיצוני (Safari) להמשך אבחון ותשלום באתר. מוודא ש**בתוך האפליקציה אין מחירים ואין כפתור קנייה דיגיטלית**.
**תוצאה:** עומד בכללי אפל, והזרימה שתיארת — מצטרף חדש עובר לדפדפן לאבחון ותשלום.

### שלב 4 — הגשה לחנות
**סוכן הקוד:** מכין build סופי, מעלה ל-App Store Connect.
**אתה:** ממלא את פרטי האפליקציה (תיאור, צילומי מסך, קטגוריה, מדיניות פרטיות), מגיש לבדיקה.
**תוצאה:** בדיקת אפל ~1–3 ימים → אפליקציה זמינה להורדה.

## 4. שני מוקשים לאישור אפל — לשים לב

1. **תשלומים (Guideline 3.1.1):** אסור מחיר או כפתור רכישה דיגיטלית בתוך האפליקציה. מודל ה-reader שלך פותר את זה — נשמור על זה בקפדנות. "להצטרף" = פתיחת דפדפן, בלי להציג מחיר בתוך האפליקציה.
2. **פונקציונליות מינימלית (Guideline 4.2):** אפל דוחה מעטפת webview "ערומה". מה שמציל אותנו: onboarding נייטיב + מסך כניסה + פוש נייטיב = ערך נייטיב אמיתי. שלבים 1–2 מכסים את זה.

## 5. בריף לסוכן הקוד (להעביר כשמתחילים)

> **משימה:** הפיכת אתר מיאושי (Next.js 14, פרודקשן על Vercel, branch `game`) לאפליקציית iOS דרך **Capacitor**, עם פוש דרך **OneSignal**, במודל reader-app (תשלום נשאר בדפדפן).
>
> **אילוצים:**
> - לא לגעת בלוגיקת התשלום/Cardcom. האפליקציה לא מבצעת תשלומים.
> - לא להציג מחירים או כפתור קנייה דיגיטלית בתוך ה-webview של האפליקציה.
> - לעבוד מול branch הפרודקשן `game`.
> - אין npm/pnpm install מול תיקיית mioshy הממונטטת (מגבלת FUSE) — לערוך package.json ידנית.
>
> **שלב 0:** הוסף Capacitor + פלטפורמת iOS. הגדר `server.url` לדומיין הפרודקשן כך שה-webview טוען את האתר החי. ודא build תקין שנפתח ב-Xcode ורץ על מכשיר.
>
> **שלב 1:** ללא onboarding. בפתיחה: אם המשתמש מחובר → טען ישר את ה-shell (`/[locale]/(shell)/my/today`); אחרת → מסך ההתחברות הקיים (`/auth`). הגדר את האפליקציה כ-**iPhone-only** ל-v1.
>
> **שלב 2:** שלב את ה-OneSignal Capacitor plugin. בקש רשות פוש אחרי login. קרא ל-`OneSignal.login(<supabase user id>)` כ-external ID. הוסף בצד השרת שליחת פוש דרך OneSignal REST API (targeting ב-external IDs) בנקודות: הודעת מומחה חדשה (`postExpertReplyToItem` / `postExpertReplyToChannel` ב-`app/actions/journey-messages.ts`) ותוכן/שיעור חדש שמשוחרר. הקשה על פוש פותחת deep-link לראוט הרלוונטי (למשל `/my/expert`).
>
> **שלב 3:** כפתור "להצטרף"/CTA לא-מנוי פותח דפדפן חיצוני (`@capacitor/browser` או `window.open` חיצוני) לאתר. ודא שאין UI של מחיר/קנייה בתוך האפליקציה.
>
> **שלב 4:** הכן build להעלאה ל-App Store Connect. ספק הוראות הגשה.

## נספח א' — Onboarding: קופי + פרומפט לתמונות

### הקופי (3 מסכים)

**מסך 1 — ברוכים הבאים**
- כותרת: *המסע הזוגי שלכם, עכשיו בכיס*
- משנה: כל מה שבניתם במיאושי מחכה לכם במקום אחד, נגיש בכל רגע.

**מסך 2 — המלווה**
- כותרת: *מלווה אישי, במרחק הודעה*
- משנה: שאלה שעולה באמצע השבוע? כתבו למלווה שלכם ישירות מהאפליקציה וקבלו מענה אישי.

**מסך 3 — נוטיפיקציות + כניסה**
- כותרת: *לא תפספסו אף רגע במסע*
- משנה: נעדכן אתכם כשמחכה פרק חדש או תשובה מהמלווה, כדי שתמשיכו בקצב שלכם.
- כפתור: *בואו נתחבר* → מסך ההתחברות.

> גרסת מסך אחד (אם מקצרים): כותרת "המסע הזוגי שלכם, עכשיו בכיס" + משנה ממסך 1 + כפתור "בואו נתחבר".

### פרומפט לסוכן הקוד — ייצור התמונות

> צור 3 איורי onboarding + אייקון אפליקציה למיאושי. סגנון אחיד לכל הסט.
>
> **שפה ויזואלית (מותג מיאושי):** פרימיום, אינטימי, חמים ורגוע. רקע כהה בגוון שזיף עמוק (#0D0429 / #150829) עם זוהר רך ביין (#B83C4D) וורוד-רוז (#fb7185, #E9C4CA) ונגיעות סגול (#e879f9). אסתטיקה מאוירת/אבסטרקטית עדינה — לא צילום, לא איור ילדותי. בלי טקסט בתוך התמונה. בלי פנים מפורטות (צללית/רמיזה בלבד, להימנע מ-uncanny).
>
> **פורמט:** איורים לאונבורדינג — portrait מלא, יחס ~9:19.5 (מתאים ל-1290×2796). אייקון — ריבוע 1024×1024, בלי שקיפות, בלי פינות מעוגלות.
>
> **תמונה 1 (ברוכים הבאים):** שני אנשים קרובים, רמז למסע משותף — קו/שביל זוהר עדין שמחבר ביניהם, אווירת חום ושייכות.
> **תמונה 2 (המלווה):** רמז לשיחה אישית ותומכת — בועות הודעה מופשטות בזוהר רך, תחושת ליווי קרוב.
> **תמונה 3 (להמשיך במסע):** התקדמות עדינה — נקודות/פרקים לאורך שביל מואר, תחושת המשכיות וקצב אישי.
> **אייקון:** סמל מותגי תמציתי של מיאושי על רקע שזיף-יין מדורג; פשוט, מזוהה גם בקטן. (אפשר לבסס על העיצוב/לוגו הקיים ב-`public/mioshy-white.svg`.)
>
> מסור את כל התמונות בגדלים הנכונים, מוכנות לשילוב במסכי ה-onboarding ובאייקון האפליקציה.
