>

## 1. הקדמה - למה אנחנו פה

### 1.1 מה קרה היום (ה־flow השבור)
1. משתמש סיים אבחון (35/35 שאלות).
2. לחץ "הצטרפות לשירות" → Cardcom.
3. **התשלום עבר באיטיות גבוהה** (חוויה של חוסר ודאות).
4. אחרי האישור הופנה ל־**שני עמודי ביניים ריקים** ("פתיחת המסע שלכם", "ציר זמן ריק").
5. **המערכת שלחה אותו לעשות אבחון מחדש** - אבחון שכבר השלים. זה הקריטי ביותר.
6. עמוד `/my` עצמו לא משדר "אתה משתמש פעיל בליווי" - הוא נראה כמו דף שיווקי שני.

### 1.2 העיקרון המוביל
> **ברגע שהמשתמש משלם - הוא לא רואה יותר אף שלב מקדים. נקודה.**
>
> "המסע שלכם רק מתחיל" של תקופת ה־onboarding נגמר ברגע התשלום.
> מה שצריך לראות עכשיו: **התוכן שהמומחים יעדכנו אותו בו**, ולא feedback של "נא להתחיל".

## 2. עקרונות מוצר - קריטריוני קבלה

| עיקרון | המשמעות בקוד |
|--------|--------------|
| **Entitlement-first navigation** | כל עמוד פוסט-התחברות בודק קודם: "מה המשתמש רכש?" - ומציג רק את הרלוונטי |
| **Marketing pages = pre-login only** | משתמש מחובר לא רואה דף שיווקי לעולם |
| **No re-entering completed flows** | אבחון שהושלם, רכישה שנסגרה, הזמנה שנשלחה - לא מציגים שוב |
| **Header reflects state** | ההידר "משחקים / ליווי / למבוגרים" מוסתר ברירת המחדל; מציג רק מה שהמשתמש רכש |
| **Single dark-cinematic visual language post-login** | כל העמודים הפוסט־התחברות עם רקע כהה, blobs נעים, אווירת homepage |

## 3. אדריכלות עמודים - מה יהיה

### 3.1 לפני התחברות (Anonymous / Guest)
| Route | מה מוצג |
|-------|---------|
| `/` | Homepage שיווקי (הקיים) |
| `/[locale]/journey` | עמוד שיווקי של "ליווי עם מיאושי" + CTA |
| `/[locale]/games` | עמוד שיווקי של משחקי זוגות + CTA |
| `/[locale]/adults` | עמוד שיווקי של "למבוגרים בלבד" + CTA |
| `/[locale]/auth` | התחברות / הרשמה |

> בהידר: מציגים את 3 הקישורים השיווקיים (משחקים / ליווי / למבוגרים) **כל עוד המשתמש לא מחובר**. אחרי התחברות - מוסתרים.

### 3.2 אחרי התחברות (Authenticated)
| Route | מה מוצג | מי רואה |
|-------|---------|---------|
| `/[locale]/my` | "המיאושי שלי" - דשבורד אישי | כל מחובר |
| `/[locale]/my/journey` | תוכנית המומחים שלי | רכש subscription journey |
| `/[locale]/my/games` | המשחקים שלי + ארכיון לרכישה | רכש journey OR קנה משחק |
| `/[locale]/my/adults` | חוויות "למבוגרים בלבד" שלי + תוכן זמין החודש | רכש journey OR קנה משחק־adults |
| `/[locale]/my/account` | **חדש** - חשבון, חשבוניות, ניהול subscription | כל מחובר |
| `/[locale]/my/account/invoices` | חשבוניות קודמות | כל מחובר |

> בהידר אחרי התחברות: רק קישורים **שהמשתמש זכאי אליהם** - בהתאם ל־`getUserEntitlements`.

## 4. Flow אחרי תשלום - ה־redirect הנכון

### 4.1 מה צריך לקרות
```
┌────────────────────────────────────────────────────────────────┐
│  Click "הצטרפות לשירות" (in AnalysisSummary)                   │
│            ↓                                                   │
│  POST /api/billing/checkout/create                             │
│            ↓                                                   │
│  Redirect to Cardcom                                           │
│            ↓                                                   │
│  User enters card → Cardcom processes                          │
│            ↓                                                   │
│  Cardcom callback (indicator) → activates subscription         │
│            ↓                                                   │
│  User redirected to /[locale]/billing/success                  │
│            ↓                                                   │
│  /billing/success polls until status=paid                      │
│            ↓                                                   │
│  ⭐ NEW: redirect IMMEDIATELY to /[locale]/my                   │
│            (NOT to /journey/assessment, NOT to journey/timeline)│
└────────────────────────────────────────────────────────────────┘
```

### 4.2 מה לתקן בקוד
- **`/[locale]/billing/success/content.tsx`** - אחרי `phase=active`, redirect אוטומטי ל־`/[locale]/my` תוך שנייה (לא להציג את המסך הנוכחי עם "Go to Library" וכו').
- **למחוק / לעקוף** את המסכי "פתיחת המסע שלכם" + "ציר זמן ריק" אחרי תשלום.
- **`/journey/assessment` PROTECTED** - אם המשתמש כבר השלים (current_step === total) ויש לו subscription פעיל - redirect ל־`/my/journey`. אסור שיופיע שוב מסך אבחון.

## 5. עמוד "המיאושי שלי" - `/[locale]/my`

### 5.1 מה רואים שם
דשבורד מסודר ב־3 רצועות:

#### רצועה 1: כרטיסי המוצרים שיש לי (compact, ללא אייקונים)
- כרטיס של כל מוצר שהמשתמש זכאי אליו
- **גודל הכרטיס: חצי מהגודל הנוכחי**
- **בלי אייקון בראש** - רק טקסט והזמנה לפעולה
- מבנה כרטיס:
  ```
  [שם המוצר]                        [→ כניסה לחדר פרטי]
  [תיאור קצר 1 שורה]
  ```
- כפתור CTA: לפי המוצר -
  - Journey: `כניסה לחדר פרטי` (לא "להתחלת האבחון"!)
  - Games: `המשחקים שלי`
  - Adults: `החדר הסגור`

#### רצועה 2: קוד הזוג (PairCode) + הזמנת בן/בת זוג
- **רק אם עוד אין partner**
- בכרטיס "ליווי עם מיאושי" עצמו (למעלה)
- כשנוסף partner → הקוד נעלם אוטומטית

#### רצועה 3: Quick links (footer)
- **לא בכרטיסים גדולים** - שורה דקה
- "החשבון שלי" → `/my/account`
- "חשבוניות" → `/my/account/invoices`
- "תמיכה"

### 5.2 מה מוסר מהעמוד הנוכחי
- **לא** "להתחלת האבחון" - האבחון נגמר
- **לא** "40 שאלות, דוח אישי..." - לא עוזר אחרי שכבר רכשתי
- **לא** הסבר על מה כולל המוצר - זה היה רלוונטי לפני הרכישה, לא אחריה
- **לא** קישורים שיווקיים בהידר (`משחקים / ליווי / למבוגרים`)

### 5.3 רקע ויזואלי
- **רקע כהה** (כמו ה־homepage hero)
- **עיגולים זזים אנימטיבית** (blobs ב־blur, motion)
- **טיפוגרפיה לבנה / קרם**
- אווירה: "אזור פרטי, פרמיום, אינטימי"

## 6. עמוד "ליווי עם מיאושי" - `/[locale]/my/journey`

### 6.1 מטרת העמוד
**להציג את התוכן שהמומחים העלו / יעלו עבור המשתמש.**
זהו ה־"חדר הפרטי" שלו אחרי הרכישה.

### 6.0 גישה לעמוד - Entitlement gate
**רק** למי שיש subscription פעיל ל־journey. אחרים שינסו לגלוש ישירות → redirect ל־`/[locale]/journey` (השיווקי) עם CTA **"להתחיל אבחון חינם"**.

### 6.2 מבנה ברירת מחדל (Phase 1 - מה שחייב לקרות עכשיו)

```
┌─────────────────────────────────────────────────────────────┐
│  שלום [שם],                                                │
│  ברוך הבא לחדר הפרטי שלכם.                                  │
│                                                             │
│  ┌─ Today / Open ─────────────────────────────────────┐    │
│  │  [קטגוריה גנרית - מותאמת לעדיפות שבחרת באבחון]    │    │
│  │  ────────────────────────────────────────          │    │
│  │  המומחים שלנו יעדכנו אתכם בעמוד הזה בקרוב          │    │
│  │  על תוכנית עבודה. כל מה שצריך לעשות זה             │    │
│  │  להיכנס לפה.                                        │    │
│  │  [כפתור: הוסיפו את העמוד למועדפים]                 │    │
│  └─────────────────────────────────────────────────────┘    │
│                                                             │
│  ┌─ Coming up ────────────────────────────────────────┐    │
│  │  [Placeholder - locked items]                       │    │
│  │   🔒 ייחשף בהדרגה                                   │    │
│  └─────────────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────────────┘
```

**הקטגוריה הגנרית** = ה־priority שבחר ב־ranking של האבחון:
- communication → "תקשורת זוגית"
- intimacy → "מיניות ואינטימיות"
- emotional_connection → "אהבה וחיבור רגשי"
- friendship → "חברות ושותפות יומיומית"
- family → "משפחה, הורות ולחצים"

### 6.3 Phase 2 (כשהאדמין יוסיף תוכן)
- כל אייטם שהאדמין יקצה למשתמש (`journey_assignments` או `journey_scheduled_items`) יופיע ברצועת "Today / Open"
- אייטם שהושלם → נעבר ל"Done"
- אייטם עתידי → "Coming up"

### 6.4 מה מוסר מהעמוד הנוכחי
- **לא** Pair-code - עבר ל־`/my`
- **לא** "התוכן שלכם", "המסלול שלכם" - מילות מילוי שלא אומרות דבר
- **לא** קישור לאבחון - הוא נגמר

## 7. עמוד "משחקים לזוגות" - `/[locale]/my/games`

### 7.1 הקטלוג המוצג
3 משחקים קיימים - **בדיוק אותם שמופיעים בעמוד השיווקי הקיים**:
- "כנות ואתגר" (Truth & Dare)
- "גלגל הזוגיות" (Wheel)
- "סולמות ונחשים" (Snakes & Ladders)

> אסור להוסיף שמות גנריים. השמות זהים בין pre-login ל־post-login.

### 7.2 פריסה - 2 בשורה
המשחקים מוצגים ב־**2-column grid**:
```
┌─────────────────────┬─────────────────────┐
│  [כנות ואתגר]       │  [גלגל הזוגיות]     │
└─────────────────────┴─────────────────────┘
┌─────────────────────┐
│  [סולמות ונחשים]    │
└─────────────────────┘
```
- מובייל: 1 בשורה
- דסקטופ + טאבלט: 2 בשורה

### 7.3 לוגיקת הצגה (CTA per game)
- **כל המשחקים נראים תמיד** (לא מסתירים נעולים)
- ה־CTA בכל כרטיס משתנה לפי entitlement:

| מצב משתמש | CTA על הכרטיס |
|-----------|---------------|
| לא רכש כלום | "רכישה / משחק חינם 7 ימים" |
| Journey subscription פעיל | "שחק עכשיו" (כל המשחקים כלולים) |
| Games subscription בלבד | "שחק עכשיו" |
| רק קנה game-bundle (one-time) | "שחק עכשיו" - רק על המשחקים שקנה |
| לחיצה על כפתור "פרטים" | מעבר לעמוד פרטי המשחק שכבר קיים |

### 7.4 שימוש חוזר בעמודי פרטי משחק
- כפתור "פרטים נוספים" בכל כרטיס → עמוד פרטי המשחק הקיים (לא לבנות חדש)
- ה־header/footer באותו עמוד מתעדכנים לפי auth state

## 8. עמוד "למבוגרים בלבד" - `/[locale]/my/adults`

### 8.1 הקטלוג המוצג
**אותם המשחקים שמופיעים בעמוד השיווקי הקיים** (`/[locale]/adults`) - אותם הכרטיסים, אותם הצילומים, אותו עיצוב. ה־storefront הקיים כבר עושה את העבודה.

### 8.2 לוגיקת הצגה - לפי מה שהמשתמש קנה

#### מצב א - לא רכש כלום
כל המשחקים מוצגים. כל אחד עם:
- תיאור קצר
- כפתור **"רכישה"** (מעביר לעמוד התשלום של אותו משחק)
- כפתור **"פרטים"** (מעביר לעמוד פרטי המשחק שכבר קיים)

#### מצב ב - רכש את **ליווי עם מיאושי**
- לפי 8.4 - זכאי ל־**משחק־adults אחד בחודש**.
- אם **עוד לא בחר את המשחק החודשי**: כל המשחקים מסומנים כ"זמין החודש - בחר ופתח". לחיצה → מוסיפה אותו ל־`couple_entitlements` ומסמנת את החודש כ"נצרך".
- אם **כבר בחר**: המשחק שבחר מסומן "פתוח", השאר עם CTA רכישה.

#### מצב ג - קנה משחק־adults בודד (one-time)
- **המשחק שקנה** מסומן כ־**פתוח** (סימון ויזואלי ברור - תג "שלך" בפינה, או צבע אחר)
- **כל שאר המשחקים** מציגים:
  - תיאור קצר
  - כפתור **"רכישה"** → מעבר לעמוד התשלום
  - כפתור **"פרטים"** → מעבר לעמוד פרטי המשחק

### 8.3 מבנה ויזואלי
```
┌────────────────────────────────────────────────┐
│  [כותרת + tagline של ה־storefront הקיים]      │
│                                                │
│  ┌───────────┬───────────┬───────────┐         │
│  │ [שלך ✓]   │ [נעול 🔒] │ [נעול 🔒] │         │
│  │ פתח       │ רכישה|פרט │ רכישה|פרט │         │
│  └───────────┴───────────┴───────────┘         │
│                                                │
│  ... כל שאר המשחקים בקטלוג                    │
└────────────────────────────────────────────────┘
```

### 8.4 לוגיקת זכאות חודשית (Journey subscription)
**Subscription ה־journey כולל משחק־adults אחד בחודש קלנדרי.**

יישום:
- שדה חדש בטבלת `subscriptions`: `adults_monthly_used_at TIMESTAMPTZ NULL` - מתי נוצל בחודש הנוכחי
- בכל בקשה לעמוד `/my/adults`, השרת בודק:
  - אם `adults_monthly_used_at` הוא NULL **או** שהיה לפני תחילת החודש הנוכחי - המשתמש **זכאי** עכשיו לבחור משחק
  - אחרת - המשתמש **כבר ניצל** את החודש; ההצגה כמו במצב ג
- ב־1 לכל חודש (cron עתידי), אפס את כל ה־`adults_monthly_used_at` של subscriptions פעילים - או חישוב נכון לפי `>= start_of_current_month`

### 8.5 כפתורי הפעולה (כל מצב)
| מצב הכרטיס | CTA ראשי | CTA משני |
|------------|----------|----------|
| שלי (פתוח) | "פתח" | - |
| זמין החודש דרך מנוי | "פתח (חודשי)" | "פרטים" |
| נעול / לא רכש | "רכישה" | "פרטים" |

## 9. עמוד "החשבון שלי" - `/[locale]/my/account` (חדש)

### 9.1 מה יש שם
- **פרטים אישיים** - שם, מייל, טלפון, סיסמה (עדכון)
- **המנוי שלי** - איזה plan, מתי מתחדש, ביטול
- **חשבוניות** - כפתור ל־`/my/account/invoices`

- **Export Data** (אם רלוונטי לרגולציה)

### 9.2 מטרה
לאסוף לעמוד אחד את כל ה־"סלמיני אדמיניסטרטיביים" שכרגע פזורים על העמודים הראשיים.

## 10. ניהול הרשאות (Entitlements) - חדש

### 10.1 פונקציה מרכזית: `getUserEntitlements(userId)`
חוזרת אובייקט:
```ts
{
  hasJourney: boolean,        // active subscription ל־journey
  hasGames: boolean,          // active subscription ל־games OR journey
  hasAdults: {
    monthly_included: boolean,        // הזכאות החודשית (מ־journey)
    monthly_used: boolean,            // האם נצרכה החודש
    next_available_at: string | null, // מתי תהיה הבאה
    one_time_owned: string[],         // game_ids שהמשתמש קנה ספציפית
  },
}
```

### 10.2 שימוש
- בכל עמוד `/my/*` - `getUserEntitlements` ב־server component
- מסנן נווט בהידר
- מסנן את התוכן של כל עמוד

### 10.3 מקום בקוד
מומלץ: `lib/entitlements/getUserEntitlements.ts` (כבר קיים - להרחיב)

## 12. עיצוב ויזואלי - כל ה־`/my/*`

### 12.0 עיקרון על: לא להמציא את הגלגל
**שימוש חוזר ב־UI הקיים בעמודים השיווקיים.** כל מוצר כבר מוצג בעמוד שיווקי לפני התחברות עם כרטיסים, גלריות, צבעים, וטיפוגרפיה. הכרטיסים האלה - בדיוק כמו שהם - מועברים לעמודים הפנימיים.

**ההבדל היחיד בין pre-login ל־post-login:**
1. **Header / Footer** - משתנים לפי auth state (כפי שמוגדר בחלק 11)
2. **CTA על הכרטיס** - משתנה לפי entitlement (ראה חלק 6.4 + 7.2 + 8.2)

**אסור** לבנות שפה ויזואלית שלישית. **כן** לקחת את הכרטיסים השיווקיים הקיימים, להעתיק אותם, ולהחליף את ה־CTA בלבד.

### 12.1 רקע
- שימוש חוזר ברקעים הקיימים של העמודים השיווקיים. כל מוצר עם הרקע שלו (journey/games/adults).
- **רק** עמוד `/my` (ה־dashboard) מקבל רקע כהה־קולנועי חדש, **כי אין לו אנלוג שיווקי**.

### 12.2 טיפוגרפיה
- בדיוק כמו בעמוד השיווקי המקביל לכל מוצר.

### 12.3 כרטיסים - שימוש חוזר
- מ־`/journey` (השיווקי) - אותו כרטיס משמש ב־`/my/journey`
- מ־`/games` השיווקי - אותו כרטיס משמש ב־`/my/games` (עם השינוי בחלק 7.5 לגבי מבנה 2-בשורה)
- מ־`/adults` השיווקי - אותו כרטיס משמש ב־`/my/adults`

### 12.4 כפתורי CTA - לפי auth state
ה־CTA *בלבד* משתנה לפי המצב:

| מוצר | משתמש לא רכש | משתמש רכש |
|------|-------------|-----------|
| Journey | "להתחיל אבחון חינם" | "כניסה לחדר הפרטי" |
| Games | "רכישה / נסה משחק חינם" | "שחקו עכשיו" |
| Adults | "רכישת המשחק" (לפי משחק) | "פתחו" (לפי זכאות) |

## 13. תוכנית מימוש מומלצת - פאזות

### Phase A - תקן את ה־post-payment redirect (הכי קריטי, יום עבודה)
1. עדכון `/billing/success/content.tsx`: redirect מיידי ל־`/my` ברגע `phase=active`
2. הגנה ב־`/journey/assessment/page.tsx`: אם השלים+יש subscription → redirect ל־`/my/journey`
3. מחיקת מסכי הביניים "פתיחת המסע" ו"ציר זמן ריק"

### Phase B - `/my` redesign (יומיים)
1. כרטיסים קומפקטיים ללא אייקונים
2. Pair-code בכרטיס journey, נעלם אוטומטית כשיש partner
3. רקע כהה + animated blobs
4. quick links → `/my/account`
5. הסרת טקסט "להתחלת האבחון"

### Phase C - `/my/journey` (יומיים)
1. עמוד עם header אישי + הקטגוריה שבחר ב־ranking
2. רצועת "Today / Open" עם הודעה placeholder ("המומחים יעדכנו...")
3. רצועת "Coming up" עם locked placeholders
4. הסרת ה־PairCode מכאן

### Phase D - Header gating (יום)
1. Header מציג קישורים שיווקיים רק לאנונימיים
2. Header מציג קישורי `/my/*` רק למחוברים, לפי entitlements

### Phase E - `/my/games` + `/my/adults` (3 ימים)
1. עמודי "המוצרים שלך" עם המשחקים הזכאים
2. רצועה "להוסיף עוד" עם CTA רכישה לפי plan
3. לוגיקת monthly-adults (זכאות לחודש)

### Phase F - `/my/account` (יום)
1. עמוד חדש עם פרטים אישיים, subscription, חשבוניות
2. Move buttons מכאן

### Phase G - Visual polish (יומיים)
1. Animated background על כל `/my/*`
2. כרטיסים בסגנון "החדר הסגור"
3. ארד accents

**Total: ~12 ימי עבודה** (סבירות אופטימית)

## 14. סיכום - Acceptance Criteria

הפיצ'ר נחשב לסגור כש:

- [ ] משתמש שלוחץ "הצטרפות לשירות" → תשלום → **לא** רואה אבחון לעולם, **לא** רואה מסכי ביניים ריקים
- [ ] `/my` הוא דף קומפקטי, רקע כהה, כרטיסים קטנים בלי אייקונים
- [ ] קוד הזמנה לבן/בת זוג מוצג רק אם עדיין אין partner
- [ ] קישורי "חשבון" / "חשבוניות" עברו ל־`/my/account`
